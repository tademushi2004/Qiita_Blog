> 本記事では、Qiita CLIでの執筆時に発生する「画像のパス管理」と「画像サイズの肥大化」という2つの課題を、Git Hooks（Husky）を活用して完全に自動解決する独自のパイプライン構築法をご紹介します。

## はじめに

みなさん、技術ブログ書いてますか？
技術ブログを書くとき、文章と同じくらい重要なのが「図解」や「スクショ」などの画像ですよね。

でも、ローカルでMarkdownを書くとき、こんな悩みを抱えたことはありませんか？
「プレビューで確認するために相対パスで書いたけど、いざ公開するときにURLを書き換えるのが面倒くさい……」
「リポジトリに巨大なPNG画像をそのままコミットしてしまって、Gitが重くなる……」

今回は、そんな地味で面倒な「画像周りの管理」を、人間が一切意識しなくてよくなる**「全自動・画像変換＆最適化パイプライン」**を作ってみました。

## 結論：コミットするだけで全部終わる

一番おいしいところからお見せします。
この環境を構築すると、記事の執筆体験はこうなります。

1. **ただ書くだけ**: ローカルの `images/` フォルダに画像を置き、Markdownには `![図解](https://raw.githubusercontent.com/tademushi2004/Qiita_Blog/main/public/avif/test.avif)` と普通に書きます。VSCodeで普通にプレビューできます。
2. **ただコミットするだけ**: 記事が完成したら `git commit` を叩きます。

**たったこれだけです。**
コミットした瞬間に、裏側で以下の「魔法」が自動発動します。

* 巨大なPNG画像が、次世代軽量フォーマットの「AVIF」に一括変換される。
* Markdown内の `images/xxx.png` というローカルパスが、GitHubのRaw URL（公開用URL）に**自動的に書き換わる**。
* 変換後のファイルが自動的にコミットに含まれる。

あとは `git push` するだけで、Qiitaへの公開まで終わってしまいます。
まさに、人間は「書くこと」だけに集中できる環境です。

## どうやって実現しているのか？（仕組みの解説）

### 全体アーキテクチャ

この仕組みの肝は、Gitの **pre-commit フック (Husky)** と、**lint-staged** の組み合わせです。

1. `husky` と `lint-staged` を使って、Markdownファイルがコミットされようとした時をフックします。
2. フックされたタイミングで、自作のPythonスクリプト（`convert_to_avif.py`）を走らせます。
3. このスクリプトが「画像のAVIF化」と「Markdownファイル内の文字列置換（正規表現）」を瞬時に行い、変更結果を `git add` して元のコミットにねじ込みます。

### 構成要素とスクリプト

用意するのは非常にシンプルです。

#### 1. lint-staged の設定
`package.json` に以下のような設定を記述します。

```json
  "lint-staged": {
    "public/*.md": [
      ".venv/Scripts/python.exe scripts/convert_to_avif.py"
    ]
  }
```

#### 2. 画像変換スクリプト
Pythonの `Pillow` ライブラリを使用して、画像の変換とテキストの置換を行います。
コードの詳細は割愛しますが、やっていることは以下の正規表現マッチングです。

```python
# 執筆用パスを GitHub URL に変換
pattern = re.compile(r'(^|\s|\(|\[)images/([^\s\)]+)\.(png|jpg|jpeg)')
replacement = rf'\1https://raw.githubusercontent.com/.../public/avif/\2.avif'
```

この正規表現により、Markdown特有の記法 `![alt](path)` を正確に検知し、安全にURLを書き換えることができます。

## 逆の操作（公開済みの画像を直したい場合）

公開後、「やっぱりこの画像だけ差し替えたいな……」となることもあります。
しかし、ローカルのMarkdownファイルはすでにGitHubのURLに書き換わってしまっています。

そこで、VSCodeのタスクとして**「画像の差し替え（執筆モードへ）」**というタスクを用意しました。これを実行すると、スクリプトに `--local` オプションが付与されて走ります。

```python
# 執筆モードへ巻き戻す
pattern = re.compile(r'(^|\s|\(|\[)' + re.escape(github_avif_url) + r'/([^\s\)]+)\.avif')
replacement = r'\1images/\2.png'
```

これにより、一瞬でMarkdown内のパスが `images/xxx.png` に戻るため、再びVSCodeのプレビュー環境で画像を差し替えてプレビューし直すことが可能になります。

## まとめ

画像管理を自動化することで、執筆のモチベーションを下げる要因を一つ潰すことができました。
「人間はミスをする生き物である」という対立的計画法の視点から、**「変換スクリプトを実行し忘れる」というヒューマンエラーそのものを物理的に起こせなくする**（コミット時に強制実行する）アプローチは、非常に強力です。
